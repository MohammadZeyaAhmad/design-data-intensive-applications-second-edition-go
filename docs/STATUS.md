# Implementation status

Updated 12 November 2026. The saved plan under `docs/plan/` is the original design baseline. This file records the actual implementation. Full book coverage remains the final release gate.

## Working implementation

Implemented: a Go API, inventory and Ordering contexts, separate durable workers, PostgreSQL migrations, tenant-bound authentication, transactional request identity, outbox/inbox, ordered projections, quarantine, a guide CLI, Compose, CI, concurrency/failure tests, and a lost-update lab.

The second increment adds database-clock reservation expiry, explicit allocation reversal, an immutable order event store, expected-version commands, full replay, legacy-event upcasting, checksum-validated snapshots, keyset history, asynchronous order views, and a per-stream rebuild that can run alongside appends. Both contexts recover through worker/API restarts. That increment established 19 real PostgreSQL integration tests.

The third increment adds Catalog price versions/quotes, explicit published contracts, a durable checkout process manager, an authenticated HTTP provider simulator and a balanced immutable capture/refund journal. Resource-close markers fence delayed reserve/capture calls; source outcome facts fence stale confirmation/compensation. The full suite now has 30 real PostgreSQL integration tests plus provider-outage/worker-restart HTTP verification.

The fourth increment adds warehouse-scoped stock and event ordering, pinned checkout sourcing, a separate Fulfillment context, durable confirmation dispatch, immutable shipment history, expected-version warehouse commands and idempotent physical stock handoff. The suite now has **42 real PostgreSQL integration tests**, plus real HTTP/API/worker-restart shipment scenarios.

The fifth increment adds versioned actor/correlation/cause/origin-request envelopes across all six contexts and the provider, server-owned request identity, immutable origin/dispatch/cancellation provenance, and tenant-scoped local workflow controls. Pause/resume/retry preserves business progress and resource IDs, checks live leases, and atomically records an immutable audit and saved response. The suite now has **55 real PostgreSQL integration tests**, plus a CLI/HTTP pause-restart-resume and lineage scenario.

The sixth increment adds a pinned optional Kafka profile for four delivery lanes, separate publication cursors, a durable transport inbox, manual offset acknowledgment, fixed partition keys, source validation, stream-scoped quarantine and audited retry. The **65 PostgreSQL integration tests** are supplemented by **three isolated real-Kafka tests** for acknowledgment loss, durable-stage checkpoint loss, database-stage failure and consumer-group rebalance. Existing business flows and the broker outage/publisher-kill drill run through Kafka.

The seventh increment adds a real Temporal checkout adapter using the same business feature, immutable engine ownership, atomic activity result receipts, durable control wake signals, native cancellation compensation, bounded workflow histories and supported versioning. The suite now has **71 PostgreSQL integration tests**, **three real-Kafka tests**, and **three real-Temporal tests**, including worker replacement after five external stages and replay of an actual pre-version-marker history. Both checkout engines pass the same HTTP business outcome suite. A real server/worker SIGKILL drill preserves run identity and recovers an in-flight payment after natural lease expiry.

The eighth increment adds a persistent Go LSM storage lab with checksummed WAL framing, sorted immutable runs, sparse indexes, Bloom filters, tombstones, size-tiered and leveled compaction, atomic manifests, sync/async durability fences and a single-writer lock. Map-oracle tests, an independent power-loss filesystem model and **21 real process-kill boundaries** verify recovery. A synthetic warehouse workload compares the append-log baseline, both policies and **bbolt 1.4.3**, with repeated timing/space reports. Production contexts retain PostgreSQL authority.

The ninth increment adds the custom page-based B+ tree: bounded CRC-protected pages, exact separator routing, splits/borrows/merges, root collapse, linked-leaf ranges, persistent free-page reuse and full-page redo with restartable recovery. Reference/occupancy tests, modeled torn writes, initialization faults and **18 native checkpoint/recovery cases** verify the implementation. The shared warehouse runner now compares **five stores**; the dedicated tree report also deletes, reopens and reinserts the live set to verify allocation reuse. Common key/value types, file I/O and the fault model are shared across the independent storage labs.

The tenth increment adds transactional heap/clustered/secondary/covering layouts and a volatile ordered memory index for the same warehouse queries. Randomized rekeys/deletes, precommit rollback injection, prefix isolation and durable reopens verify index maintenance. A controlled four-store runner records sorted/shuffled mutations, amplification, warm/reopened reads, compaction and repeated variance. Real PostgreSQL multicolumn and covering plans preserve results and demonstrate zero heap fetches after explicit vacuum. The suite now has **72 PostgreSQL integration tests**, alongside the existing Kafka/Temporal suites. Cold-OS-cache/device trials remain explicit gaps.

The eleventh increment adds a bounded compressed column format, sorted immutable segments, validated row-group zone maps, a durable versioned delta and tombstone floors. Scalar AST, bitmap-batch and actually compiled native Go predicates match independent row queries, including SQL unknown values, updates and deletes. All eight tenant-preserving cube groupings update atomically with facts and match full reductions before/after rebuild and reopening. Eight native publication-kill cases and three codec/expression fuzzers supplement the lab tests. Compilation/process costs, logical byte counters and the absence of explicit SIMD/distributed cloud operation remain visible in the report.

The twelfth increment adds tenant-local inverted text/position indexes, bounded fuzzy matching, a multidimensional KD tree, exact cosine/Euclidean retrieval and an actual seeded HNSW implementation. Persistent source versions/tombstones rebuild derived structures after changes and reopening. A seventh Search context provides authenticated PostgreSQL full-text/trigram/spatial APIs, immutable publication history and an optional pgvector profile. Source/model/revision fences exclude stale embeddings. The application suite now has **75 PostgreSQL integration tests**, plus **three native pgvector**, **three Kafka** and **three Temporal** tests. Repeated exact-versus-ANN reports expose recall, work, graph payload-memory estimates and six explicitly forced native HNSW plans. Synthetic vectors make no language-understanding claim.

These pieces begin several large work packages; they do not complete those packages in full.

The thirteenth increment adds normalized Catalog brands/details, ordered variants, category memberships and bounded JSONB attributes, with independent content revisions, immutable history and generated sqlc reads. Equivalent relational/flat/document/column-family experiments demonstrate copied-name anomalies, repair, schema-on-read migration and actual nested-update buffer/allocation costs. Actual sqlc/GORM mappings return identical details with 1/37/4 statements for a twelve-product fixture. Four new database tests bring the normal suite to **79 PostgreSQL tests**, alongside the existing **three pgvector, three Kafka and three Temporal tests**. The wide-column exercises model access patterns using bbolt/PostgreSQL; they do not implement a distributed wide-column engine.

The fourteenth increment adds warehouse/supplier property multigraphs in Go adjacency maps, PostgreSQL recursive CTEs and actual Neo4j/Cypher. Minimum-hop reach includes full bounded-component traversal; node-simple paths preserve parallel edge IDs, and bounded Dijkstra/native queries agree on cost and deterministic ties. An independent oracle verifies initial/property-update/vertex-delete phases, while three native integration tests exercise malicious tenant bridges, explicit path overflow and complete single-client replacement. Default reports retain 144 Go samples, 432 cross-backend samples and 15 actual plans. Existing application contexts remain unchanged; graph routing is a lab, without real sourcing/shipment authority.

The fifteenth increment adds stable RDF resource/literal identity, indexed triple sets, actual SPARQL/Fuseki/TDB2 and a completed bounded positive Datalog evaluator. Naive and semi-naive fixed points agree, with explicit language/resource bounds. Five backends answer fourteen membership questions through three fixture phases; native tests cover bags/DISTINCT, Turtle and blank-node interoperability, ownership fences, authentication and owned cleanup. Default reports retain **378 Go samples, 630 native samples and four actual SQL plans**. Three new semantic-service tests supplement the unchanged 79 normal application tests and the previous graph/pgvector/Kafka/Temporal suites.

The sixteenth increment adds a real authenticated GraphQL read endpoint over published Ordering/Catalog contracts, request-local collection batching, signed tenant/resource keyset cursors, precise decimal-string Long values and bounded query cost. Full selected answers match existing REST composition with **3/3/3 actual SQL statements for 1/10/100 lines**, versus **3/21/201** for the single-resource REST baseline. Four new PostgreSQL tests bring the normal suite to **83**, and a real API/worker HTTP check verifies nested reads, tenant scope, pagination and source freshness. Deprecated/current price fields share authorization, while frozen accepted order prices remain separate from current Catalog prices.

The seventeenth increment adds gob/JSON/XML/MessagePack/Protobuf/Thrift Binary/Compact snapshots with real generated schemas/clients, JSON Schema validation and bounded decoding. Default reports retain **126 byte/CPU samples, 28 compatibility cases, 17 relays, eight generated Thrift RPC pairs and twelve semantic observations**. Native Protobuf relays preserve unknown fields while typed projections and generated Thrift readers lose them. Numeric narrowing, ProtoJSON rename and actual Thrift Go default/presence differences are explicit. Gob uses a constrained Linux child; production event formats remain unchanged. The normal PostgreSQL suite remains **83** tests.
