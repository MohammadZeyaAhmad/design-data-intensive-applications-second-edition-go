# Actor and broker recovery

Use the [actor guide](../ACTORS.md) and `make verify ID=C05-06`. `make actors-demo` runs local/remote transient checks, `make actors-postgres` runs three disposable-database tests, and `make integration-actors` runs native Kafka recovery. An explicit `ATLAS_ACTORS_BROKERS=127.0.0.1:19094` selects an existing local broker instead of creating/removing the dedicated profile.

1. Determine which boundary was acknowledged. Tell/202 reports volatile admission. Ask may time out after acceptance or effect. Kafka publication acknowledges broker bytes. SQL receipt commit proves one local outcome. Source-offset commit proves consumer progress past a physical record.
2. Preserve the original message ID, entity key, operation and complete payload when resolving an uncertain result. In-memory receipts may already be evicted or lost after restart. Durable receipts return their original saved snapshot, not necessarily the latest stock head; issue a separate query for current state.
3. On mailbox backpressure, bound upstream work rather than spawning unlimited send goroutines. A blocked entity should not prevent another entity from executing. Check the bounded actor registry and stopped-cell status as well as queue capacity.
4. On supervised failure, resolve a new generation. Queued old-generation messages are dropped and appear in bounded diagnostic dead letters. On process replacement, obtain a new incarnation too; the old address/reference pair is rejected. Do not infer that another node cannot simultaneously own the same business entity.
5. For durable consumers, inspect PostgreSQL state, receipts and attempts separately from Kafka group offsets. A process killed before commit leaves no target effect; one killed after commit but before offset acknowledgment must be redelivered and replay its saved result. Do not delete the receipt or invent a new ID to get past the uncertainty.
6. Allow time for the actual six-second Kafka group session to expire after a hard kill. The native drill allows twenty seconds for replacement checkpoints. Assignment snapshots maintain the full owned set across cooperative add/revoke callbacks; one callback's delta is not the complete assignment.
7. A failed record stops this finite worker without source acknowledgment. Unsupported schemas/operations and changed-body conflicts require diagnosis, not blind skip/commit. Production poison-record quarantine, permanent business-rejection policy and controlled replay are separate operational work.
8. When republishing, preserve complete original encoded data. A typed old decoder can silently lose an optional field; the body-hash conflict guard detects that rewrite for a reused identity. Check the original source bytes before considering any migration or repair.
9. Reply publication and source acknowledgment are separate from the SQL transaction. Correlate replies by ID, entity and subscription; duplicate replies do not authorize another effect. An external side effect still needs its own idempotency/reconciliation contract.

The fixture retains `artifacts/actors.json`, `artifacts/actors-broker.json`, executable hashes and checkpoint/assignment files. Credentials are passed only in private child environments. Fresh databases, scoped groups and successfully created topics are removed by the harness. `make down-actors` removes only the dedicated `ddia-go-actors-test` Kafka profile and its synthetic data volume; it leaves the base application stack intact.

The profile is loopback plaintext with development credentials and a single Kafka replica. It establishes actual consumer/process recovery, not replicated durability, device power-loss recovery, global actor placement, indefinite event retention or a production retry/receipt horizon.
