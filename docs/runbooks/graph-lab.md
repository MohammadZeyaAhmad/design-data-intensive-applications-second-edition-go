# Graph profile operation and fixture recovery

Run `make verify-graph` for the complete Go/PostgreSQL/Neo4j scenario. It owns its Compose project and stops those containers on exit, including failed tests. `make up-graph` leaves the independent services running for repeated `go run ./cmd/guide verify-graph-services`; `make down-graph` stops them and retains their volumes.

The graph password is generated by `make configure` only when missing. Preserve `.env` with its volumes. Neo4j initialization credentials do not reset an existing database's password. Investigate a credential mismatch rather than deleting data or silently disabling authentication. SQL/Cypher health checks pass passwords through child environments, not command-line values or report fields.

Default loopback ports are 17433 (PostgreSQL), 17687 (Bolt) and 17474 (HTTP). The guide supports the profile's port overrides and builds private connection settings for the lab child. Native tests reject remote/admin bindings and create a fresh `atlas_graph_run_*` database under the local `atlas_test` administrator. It needs database creation permission. Cleanup drops only that owned database.

Neo4j creates unique run markers and scoped vertices/relationships under `AtlasGraph*` labels. It installs the owned identity constraints and retains them across runs. Cleanup removes the fresh run's nodes, attached relationships and marker; it does not clear unrelated runs or the whole database. If a failure leaves a scope behind, preserve the logs and identify that exact run before any manual cleanup. Never infer permission to delete other tenants/runs from a failed test.

Fixture replacement validates identities, endpoint types, positive cost, properties, degree/size bounds and then publishes one native transaction. Each client serializes that operation against its queries. After an uncertain response, rerun an owned fixture replacement with the same complete data or start a new owned run; this lab has no application command receipts, event history or cross-client cutover protocol. Native adapter cleanup errors are reported.

`ErrBudget` means all-path enumeration exceeded 256 results; it is not a successful partial answer. Narrow the supported hop/property/kind query, or use cheapest/reach when that is the actual question. Do not increase bounds until revisiting worst-case expansion and native query memory/time limits. Full reach uses the separate 511-hop bound for the maximum 512-node graph.

Go adjacency data is volatile and must be reloaded after process replacement. PostgreSQL/Neo4j provide their own storage recovery, but this increment does not certify native server crash/power-loss recovery, backups or multi-client snapshot publication. Cancellation tests cover already-canceled contexts; native driver/server timeout behavior is not a new durability guarantee. Preserve the distinction between synthetic routing results and real sourcing/shipment authority.
