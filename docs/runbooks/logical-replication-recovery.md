# Logical projection recovery drill

Scope: the isolated C06-03 fixture. It never accepts an arbitrary existing source or target through the normal demo command.

1. Run `make verify ID=C06-03`. Retain `artifacts/log-formats/native.json` and the binary provenance manifest. Check revision/dirty state, PostgreSQL version, source identity, matched state digest and both crash boundaries.
2. Bootstrap only an owned prepared target. Keep the slot's exporting connection alive and idle until the SQL transaction imports its snapshot; perform all snapshot reads in that transaction. Commit copied rows and consistent-point checkpoint atomically, then stream from it. Confirm overlapping source commits arrive through the log.
3. On a consumer failure, inspect the durable target checkpoint and source confirmed-flush position. A received frame or keepalive high-watermark is not a completed target transaction. Before-commit interruption must leave rows/audit/checkpoint unchanged; after-commit interruption can leave committed target state without source acknowledgment.
4. Resume from a valid retained position under the same source identity/incarnation. A replayed committed transaction must not create another row effect or audit receipt. A source position ahead of the target, a missing/lost slot or a changed identity requires an explicit rebootstrap/reconciliation decision. Never jump to current WAL to make the process appear healthy.
5. For schema mismatch, stop feedback at the last durable checkpoint. Verify no partial changes escaped from earlier rows in the same source transaction. Review and apply the target migration explicitly, then replay the entire transaction. Do not interpret a relation metadata frame as authorization to generate arbitrary DDL.
6. For NULL/empty/TOAST or missing-row failures, retain the relation/type contract and position. Preserve existing values for unchanged TOAST markers; an incomplete INSERT or missing UPDATE/DELETE target row is an error, not an implicit upsert. Repair the snapshot/projection or schema contract before resuming.
7. Before enabling writes on a promoted branch, fence the original source. Verify identity sequences separately: copied logical row IDs do not advance their generators. The native logical branch demonstrates collision then explicit repair; the physical branch verifies a noncolliding value while allowing WAL preallocation gaps. Logical-slot failover needs its own supported plan.
8. Review production obligations before adopting the lab: role grants, publication filters/partitions, slot retention/invalidation alarms, idle progress, initial-copy restart, two-phase/streamed transactions, schema/sequence lifecycle, source fencing and cross-major/scale tests. The current fixture retains finite protocol support and performs process kills rather than host power-loss tests.

The Compose sandbox has no persistent database volume. Native shutdown stops only captured processes; normal cancellation removes their owned data after shutdown. Source/target credentials stay in private environment/passfile state and are excluded from reports.
