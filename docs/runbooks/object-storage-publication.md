# Object storage publication and compute recovery

Scope: the bounded C06-02 lab. The executable owns its local stores, emulator, compute children and fresh S3 test prefix.

1. Run `make verify ID=C06-02` and retain both reports plus `artifacts/object-storage-binaries/manifest.json`. Check the revision/dirty state, backend labels and conditional-write contract results. Local and emulator logical state hashes must match.
2. If a writer reports conflict, read a fresh complete head/generation and decide whether the set-value intent may be explicitly rebased. Do not treat a stale read-modify-write as safe to retry automatically. Changed payloads under an existing command ID are permanent conflicts.
3. If acknowledgment is missing or the result is uncertain, reconcile or retry the identical command ID and payload. A killed compute process after head publication may have committed. The report's post-head case must return the original generation without another state change.
4. For pre-head failures, verify that readers still see the old complete generation. Inventory the private namespace after active writers stop. Retry the requested intent and require uploaded segment reuse and exactly one recovered generation. Do not publish arbitrary orphan objects merely because they appear in a listing.
5. For missing/corrupt referenced data, stop publication and retain the affected reference. A reader must fail without a partial row set. Use known immutable hashes and retained snapshot references to investigate. Never repair a bad generation by silently omitting a segment or trusting a stale cache pointer.
6. Compact through a new conditional generation and compare logical state before/after. Verify named old snapshots remain readable. The current audit retains all history; it does not delete live, historical or orphan objects. Add a separately fenced lifecycle/GC policy before reclaiming production storage.
7. Inspect cold/warm/reopened GETs and body bytes. Warm reads should still fetch the current head. Parent-process port attempts and actual S3 wire counters have different scopes; child requests are excluded from those parent totals. Add provider request, storage and egress pricing only for an identified workload/deployment.
8. The explicit cloud command requires an existing bucket and environment credentials; it allocates a fresh lab prefix, stops compute children, deletes only that prefix's keys and checks an empty listing. If cleanup fails, the command fails and prints the owned prefix. Repair its test-role permissions and remove only those identified lab objects; never delete the bucket or another prefix.

The default scoped command uses Moto's volatile emulator and makes no AWS durability or IAM claim. Native shutdown stops only captured child processes. Python runtime setup is hash pinned and rejects an unmarked existing tool directory. Production failure domains, retention, access/encryption policy, key recovery, large objects and scale remain in the complete baseline.
