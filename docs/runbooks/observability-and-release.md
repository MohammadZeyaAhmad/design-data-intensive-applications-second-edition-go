# Operational signal and release recovery

Run `make verify ID=OPS-01` against the local PostgreSQL fixture. For the actual backend profile, run `make up-observe verify-observe-live`, then `make restore-default-observe`. [The guide](../OBSERVABILITY.md) states the scope and ports. Native failure tests own disposable databases/processes; they never send paging/email/chat messages or provision cloud resources.

If a trace is missing, check whether the process enabled tracing, sampled the root, retained compatible durable context and could reach OTLP. Export failures and finite queue/sampling loss do not prove a lost business transaction. Reconcile through durable jobs, receipts, provider intent IDs and immutable journals. Never log raw request bodies, bearer keys, SQL, DSNs or tenant/resource IDs to diagnose it. The collector endpoint/credential configuration belongs in protected deployment settings, not span attributes.

A scrape 401 with a tenant key is expected. Use the independent telemetry reader credential. `make configure` preserves the private token and writes a mode-0600 file for the local Prometheus UID/GID. Keep it private; do not loosen token-file permissions or copy its contents into versioned configuration. A failing scrape target and a failing/stale audit are different alerts.

For `AtlasConsumerLag`, compare pending-source age/count and inspect the appropriate owning delivery lane. The implemented audit covers the PostgreSQL Inventory dispatcher. A quarantined record can preserve lag intentionally; do not bypass ordering or advance checkpoints merely to clear a graph. For `AtlasIntegrityFailure`, compare equal-version source/view values and use a reviewed owner repair/rebuild procedure. Do not mutate the authoritative source to match a corrupt view. The native test's direct projection repair is limited to its disposable fixture, not a general production repair command.

During planned drain or rollout, interpret audit/target absence with deployment state and production hold windows. The shipped seconds-long holds make local firing visible and require calibration before paging. No traffic provides no finite availability proof. Histogram p95 is an estimate, and server-side success does not establish caller receipt or completed checkout.

Keep `ATLAS_DURABLE_TRACE=false` until every strict reader is upgraded. The chart's reader-ready flag records an operator prerequisite; it does not discover all replay consumers. After new carriers enter retained history, disabling emission does not make an old strict consumer safe. Follow compatibility and retention gates before rollback or flag retirement. Existing [evolution recovery](schema-rollout.md) documents source schema/backfill/contraction boundaries.

For a release, verify the exact SHA's CI result, generate clean artifacts, inspect build information/SBOM/checksums and use the manual candidate workflow for provenance attestation. `go run ./cmd/releasecheck -verify -output <bundle-directory>` rejects changed files and manifest/dependency mismatch. Unsigned checksums require a trusted inventory; do not claim a signed publisher or vulnerability clearance from them. Promote a container registry digest corresponding to the tested source, never substitute a binary file hash for an OCI manifest digest.

The chart runs migration as a bounded pre-upgrade Job. Its actual PostgreSQL advisory transaction lock serializes concurrent jobs; canceling a waiting job does not authorize parallel DDL. Readiness controls traffic; dependency failure is not by itself a reason to restart a healthy worker. Retain the previous compatible image/readers and verified database recovery path before upgrades. The AWS reference remains un-applied; identity/network/SQL grants, backup restore and account-specific cost/security review are separate deployment work.
