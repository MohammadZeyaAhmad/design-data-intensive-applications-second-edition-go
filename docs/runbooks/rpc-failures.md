# RPC timeout and discovery recovery

Use the [RPC guide](../RPC.md) for limits and the local trust model. `make verify ID=C05-04` runs the isolated drill; `make up-routing verify-rpc-live` checks the Compose profile against the ordinary development HTTP API. `make down-routing` stops/removes only the three routing-profile services; it retains the base stack and its database volume.

1. On a reservation timeout, retain tenant, command key and the exact original payload. Query a known reservation ID if available, or retry with the same key while the caller budget permits. Do not mint a replacement key to discover whether the first request committed.
2. Treat `ALREADY_EXISTS`/HTTP `idempotency_conflict` as a payload identity conflict. Insufficient stock and invalid input are business failures; automatic transport retry is not their remedy. Correlation IDs diagnose requests and do not replace idempotency keys.
3. Check the standard gRPC health service, database/migration readiness and endpoint label. The proxy becomes `NOT_SERVING` when its balancer has no ready backend. `UNAVAILABLE` can be returned before work or after a lost connection; it is not proof of rollback.
4. Inspect only this deployment's tagged `atlas-rpc/<endpoint>` database sessions. Live context cancellation should stop a blocked query through CancelRequest. After SIGKILL, SQL lock/statement/idle limits bound abandoned work. Do not remove a command receipt or release business stock merely because its API process died.
5. Replace the trusted registry file atomically inside the mounted directory. Increase its revision when changing endpoints. The nonsecret endpoint directory/file must remain readable by container UID 65532 (0755/0644); replacement snapshots need that read permission too. An empty higher revision deliberately withdraws every destination. Restore a surviving peer with a newer revision; an older file is not an accepted rollback while the proxy runs.
6. A rejected registry update retains the prior valid snapshot and emits a value-free warning. Check syntax, 4096-byte/16-endpoint bounds, unique host:port entries and revision ordering. Avoid publishing tenant keys, database URLs or full environment/log dumps during diagnosis.
7. Drain a backend by removing it from new selection and allowing in-flight work to finish before stopping it. Backend/proxy graceful shutdown waits up to five seconds, then forces termination. The process-kill drill intentionally skips graceful drain to test failure recovery.

Retain `artifacts/rpc.json`, its executable manifest and relevant registry snapshot. The report separates confirmed durable replies from the client's observed timeout, records four contract-version combinations and captures database cancellation/orphan-drain timing. Its baseline adapter is a schema fixture, not a released old Atlas binary. For actual SQL binary evolution use the separate [schema rollout runbook](schema-rollout.md).

The local profile uses development bearer credentials and plaintext inside the private Compose network. Production mesh TLS/identity, authoritative registry leases, credential rotation, receipt retention, retry telemetry and external-effect reconciliation need the corresponding operational work from the original plan.
