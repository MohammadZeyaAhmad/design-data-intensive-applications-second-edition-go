# Reference service indicators

The local example target is **99.9% known-route server-response availability**, with **95% of observed handler durations at or below 250 ms**. These are illustrative objectives, not measured production SLO commitments. Actual sizing, business eligibility, windows, traffic models and error-budget policy remain C02-02/OPS work.

Availability divides the failed-response counter (5xx and 429) by a request counter with the same route/method dimensions. Its denominator deliberately has no status dimension: the first failure in a new status series otherwise disappears from an initial `rate()` window. Native Prometheus evaluates the actual counter changes; no zero denominator is replaced with an invented healthy sample. No traffic yields no finite availability evidence. Health/readiness/unmatched routes are excluded. This indicator does not prove that a caller received a response, that an accepted checkout finished, or that a read model is current. Known-route invalid client requests still affect the example denominator; a production eligibility policy needs a separate authenticated-use-case definition.

Latency uses mergeable classic histogram buckets, not an average of pod percentiles. `histogram_quantile` estimates a quantile within buckets. The 250 ms good-event ratio is separately recorded. The native finite request run produces an estimate within the first 5 ms bucket; it does not establish exact p95 timing or throughput capacity. Open-loop arrival modeling, coordinated-omission experiments and histogram approximation audits remain C02-02.

Freshness and integrity are independent. The PostgreSQL dispatcher audit reports unprocessed Inventory source count/oldest age, and compares source/view values **only at equal versions**. A lagging/missing projection is not called corruption by that comparison. It does not audit every business invariant, unknown extra rows, Kafka offsets or all contexts. Failed/stale audit evidence is not a healthy zero. Only audit-owning processes advertise the audit-enabled signal; provider/worker metric endpoints do not create false audit failures. Configured scrape-target failure has a separate alert.

The development profile deliberately uses seconds-long lag/integrity alert holds so a finite drill can observe firing and resolution. Real production windows must account for steady-state latency, rollout/drain, retention and workload. The example 5-minute availability burn rate divides error ratio by the 0.1% budget; a 14.4x burn held for two minutes is an exercise, not a calibrated paging policy. No notification destination is configured or contacted by verification.
